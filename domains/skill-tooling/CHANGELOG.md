# Changelog — skill-tooling

## 0.1.0 — unreleased

- Domain created, to hold the tool that creates, edits, audits and evaluates skills: `VERSION`, this changelog and `permissions.json`.
- Skill `authoring-skills`, with a first `SKILL.md` for its audit: `scripts/audit.py <skill-dir>` checks the frontmatter rules F1 to F13 and the name and description rules N1 to N10 the size rules Z1 to Z4, the resource rules R1 to R4, the execution rules X1 to X7, the text rule T1 and, where the repository's `.agent-conventions.toml` declares them, the convention rules C1 to C7 of the catalogue of 2026-10-03; `--portable` checks against the Agent Skills standard, `--checks` runs the repository's check commands. `scripts/frontmatter.py`, copied from `shared/frontmatter/`, reads frontmatter as a strict subset of YAML; `scripts/conventions.py` and `references/conventions.md`, copied from `shared/conventions/`, read the conventions. Its allow rule is in `permissions.json`.
- Rule C1 leaves out the `[skills] workspace`, where eval runs put their copies and outputs.
- Hook `audit_skill.py` (PostToolUse on Edit, Write and MultiEdit): audits the skill that holds the edited file and, on errors, exits 2 with one line per failing rule; warnings, a clean skill and a file outside any skill stay silent.
- `references/writing-guide.md`, cited from `SKILL.md`: the rules of form for a skill's text — the description, what goes in and what an agent already knows, the form that answers each kind of observed failure, degrees of freedom, structure, scripts and permissions, terminology, examples and templates, names, and Claude Code's own features.
- `references/create-and-edit.md`, cited from `SKILL.md`: the procedure for a new skill — the work sized to the request, the intent restated as the user gave it, whether a skill is the answer, its kind and proof, its place, research, failures observed before writing, the minimum, the audit, the comparison — and the proof each kind of change to a skill needs.
- `references/discipline.md`, cited from `SKILL.md` and from create-and-edit: for a skill that enforces a rule, a mechanical guard looked for first, pressure scenarios before the rule, the rule in plain form with its condition and safe path, rationalizations and red flags quoted from runs only, and loopholes closed one run at a time.
- `assets/templates/reference.md`, `task.md` and `discipline.md`, cited from create-and-edit and from discipline: the `SKILL.md` skeleton of each kind of skill, its description slot taking what the skill does, then when to use it; a reference's facts each with its source, a task's steps each with its check, a discipline skill's rule, safe path, and rationalizations and red flags quoted from runs. `evals/checks.py` runs the roadmap skill's template rules on them.
- Agent `skill-auditor`, read-only, on Sonnet: given a skill's folder, the writing guide's path and the static audit's output, it judges what no static rule checks — the description, the form of the guidance against the failures in the skill's evals, content an agent does not need, terminology, degrees of freedom — and answers `VERDICT: PASS` or `VERDICT: FAIL` with one line per problem. Its fixtures are under the skill's `evals/auditor/`.
- `references/audit.md`, cited from `SKILL.md`, whose audit section it replaces: the static audit, then `skill-auditor`, or the writing guide's judgments applied by the agent itself when no agent can be started, then one report, each problem with its fix and no file changed; `/skill-doctor` named for a question of a skill's cost or use.
- `SKILL.md` rewritten for the three operations, create, edit and audit: the conventions read before a create or an edit, three rules that hold for every operation — guidance answers an observed failure, the work follows the size of the request, the audit runs after any write —, the routing table, and the two scripts; its description names the three operations.
- `scripts/audit.py` and the hook `audit_skill.py` write no `__pycache__` beside the scripts they import, installed or not.
- `SKILL.md`'s first rule stated as a conditional on the kind of change: a new skill or a change meant to alter behavior starts from runs without it, any other change takes the proof that create-and-edit lists for its kind.
- Each fact the skill states names its source, the most neutral first: the Agent Skills specification and its guides, then Claude Code's pages, then what this repository probed. The writing guide's opening lists them, the standard's guides in place of the Claude platform's best practices.
- `skill-auditor`'s content judgment reports a fact about a standard, a harness or the repository stated with no source, a policy and the rule the skill exists to keep included; its terminology judgment lists the nouns that name the skill's things and searches every file for a second name. Its fixtures gain `fact-without-source.md`, and the others give the team's rule and the 30-day threshold their source.
- `scripts/audit.py --help` names what the skill names: the Agent Skills standard, the harness's rules and the repository's conventions.
- `scripts/workspace.py <skill-dir>`, cited from `SKILL.md`: validates the skill's `evals/evals.json`, naming each unknown key, missing key and wrong type, then prepares the next iteration of its evals under `<workspace>/skills/<skill-name>/` — `iteration.json` with the cases, configurations, runs, model, effort and budget; the skill without its evals, and with `--baseline` the previous version from a git revision or a folder; `base.tar`, the repository without the skill's folder, for a `repository` case; each case's `eval_metadata.json`, files and fixture, and one folder per configuration and run. `--baseline-only` prepares the baseline before the skill is written; `--reuse` takes an earlier iteration's baseline runs for each case that has not changed.
